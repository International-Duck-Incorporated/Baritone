## 4. Exact Gauntlet loop and patch integrity

```text
FETCH / READ CURRENT TEAM
-> RESPOND / SHARE SOURCE EVIDENCE
-> CLAIM UNOWNED APPROVED CARD + FILE LOCK
-> READ / DESIGN / REVIEW CONTRACT
-> MINIMAL IMPLEMENTATION + FAILING-THEN-PASSING REQUIREMENT CHECK
-> FOCUSED TESTS / FULL SUITE+BUILD / REAL SCENARIOS
-> DIAGNOSE OWN REGRESSIONS / RE-RUN
-> MEANINGFUL INDEPENDENT REVIEW / ADDRESS FINDINGS
-> INSPECT STATUS / DIFF / CHECK / STAT / AUTHOR
-> STAGE ONLY OWN INTENDED SOURCE+TEST+DOCS
-> LOGICAL COMMIT / VERIFY AUTHOR
-> FETCH / RECONCILE / RETEST IMPACTED REBASE
-> GENERATE UNIQUE NUMBERED PATCH FROM ACTUAL COMMIT
-> APPLY-CHECK AT DECLARED PARENT / COMPARE TREE
-> COMMIT PATCH+TEAM RECORDS
-> PUSH / INDEPENDENT FETCH+LS-REMOTE / ANCESTRY CHECK
-> UPDATE STATUS / HANDOFF / REVIEW NEW PEER WORK
-> REASSESS SHARED PRIORITIES / NEXT UNOWNED APPROVED CARD
```

For a product commit `C`, create the patch from that real commit (e.g. `git format-patch -1 C --stdout`) after fetching/choosing the next unreserved number. Validate in an isolated scratch worktree/index at `C^`; compare resulting product/test/doc tree with `C`. Commit the patch artifact/team record separately if needed to avoid a self-referential patch. If an unpublished commit is safely rebased, regenerate its patch header/diff and re-check before pushing. Shared pushed commits are not rewritten to refresh an artifact. No implementation patch for this planning-only package.

## 5. Review, timeout/inactive-agent recovery and handoff

**Meaningful peer review:** re-derive the predicate/call path; inspect callers/edge cases; check a falsifying scenario or mutation; name differences before agreements. Credit inherited work and independent results. A reviewer who checked an evidence bundle has not automatically approved later combat/migration architecture. A measured hold does not prove “forever” or its writer; an exact header-format observation does not mean missing commit identity. Correct hypotheses visibly rather than silently erasing them.

**Inactive recovery (proposed coordination policy):** after a missed expected checkpoint or 30–60 minutes without activity, inspect the last entry, latest messages, remote commits/patches/actual tree and any announced long-running test before deciding the agent is quiet. Send a bounded response/request and record the evidence/transfer. Preserve completed work; distinguish resting/completed from abandoned; don't overwrite status/history or seize an active file lock merely because the clock passed. This session's old Nightjar/Redshank work needs that inspection/reconfirmation, not automatic deletion.

**Durable handoff before timeout/interruption:** in Active Agents, task record and Chat, record task/owner, exact baseline/current local+last verified remote SHA, changed files, source evidence, executed commands/results, pending checks/review, patch names/baselines, dirty/staged state, blockers, approval limits and next concrete action. Save essential evidence in the repository; workspace raw logs supplement it. Do not treat excluded caches/build outputs or an unattended process as durable completion. Stop a test client when done; don't promise background continuation after the response.

**Real stop conditions:** human approval required for the next scope; exact authentication/operator capacity blocker after real attempts; no remaining authorized unowned work; user explicitly requests pause/stop; unrecoverable environment limitation with a precise handoff. Ordinary compile/test/download/TLS/rebase/push failure means diagnose, retry an appropriate changed approach, and continue independent authorized tasks—not abandonment, false green, or unauthorized scope expansion.
